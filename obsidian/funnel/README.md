# Funnel

Funnel gathers facts/cues from different sources for incorporation into an
Obsidian vault to support journaling.

## Standalone

Requires Go **1.27.1**, timezone data and both source configurations. No external Go dependencies.

```sh
GOWORK=off GOTOOLCHAIN=local go build -o /tmp/funnel ./cmd/funnel
/tmp/funnel --help
# Inject the five variables through your trusted environment/secret launcher.
/tmp/funnel sync --vault /path/to/scratch-vault --week 2026-W39 --dry-run
/tmp/funnel sync --vault /path/to/scratch-vault --week 2026-W39
/tmp/funnel sync --vault /path/to/scratch-vault
```

The vault directory must already exist. Default selection: current Madrid ISO week and its two predecessors. `--week YYYY-Www` touches only that historical week. `--dry-run` requests sources and validates existing output, but changes no files and prints no personal histories.

Configuration: `DAWARICH_URL`, `DAWARICH_TOKEN`, `PLEX_URL`, `PLEX_TOKEN`, `PLEX_USER_ID` (see `.env.example`). URLs cannot contain credentials, query strings, or fragments. Tokens go in HTTP headers. Redirects are refused. Keep HTTPS verification enabled. HTTP is supported only for an operator-approved private network or synthetic tests; it transmits credentials in cleartext. No dotenv loader is built into Funnel; do not evaluate an untrusted env file as shell code. Docker env files require plain unquoted `KEY=value`, without `export` or shell expansion; use a private compatible copy if your existing file uses shell quoting.

Plex selects one exact account name or server-local numeric ID using `/accounts`, then requests only that account's history. Ambiguous/missing selectors fail the source refresh. History time is `viewedAt`, not an invented playback start or completion claim. Missing optional metadata stays limited. Dawarich supplies existing suggested/confirmed visits; declined records are excluded. No new detection, raw GPS ingestion, geocoding, or home filtering.

Map links disclose their coordinates to Google when opened; Funnel does not query Google. Generated history is sensitive: confirm your vault remote and intended readers before authorizing publication.

## Output and safety

Only `Autogenerated/YYYY-Www Funnel.md` with schema-1 Funnel ownership is writable. Other files and older weeks are preserved. Each generated brief links to the matching weekly note (for example, `[[2026-W41]]`). Unsupported/manual format changes (including raw HTML, wikilinks or non-map links in saved cue blocks), filename collisions, symlinks, changed source identity, or concurrent target changes fail safely. Generated files are not personal-note templates and contain no personal tags or `created` field. Folder placement does **not** prove exclusion from personal Obsidian Bases; verify actual views separately.

Event-local timezone evidence wins when available; these verified transport schemas currently provide none. Times therefore use the visibly labelled `Europe/Madrid` fallback. UTC serialization and server timezone are not viewer-location evidence. Cues belong to their display-local start day; cross-midnight ends show dates. Unknown ends remain unknown. API windows include 24-hour UTC boundary padding and discard future/out-of-week starts.

A complete successful response replaces one source/week, including valid empty results. Failure keeps its previous cue blocks verbatim and labels them stale; uncovered days are unavailable. First-run failure is unavailable, never proof of no activity. Freshness/coverage/identity metadata and cue text live only in the Markdown; there is no hidden history cache. Account identity fingerprints are not anonymization. During an outage, an unverified account is explicitly labelled; known mismatches are refused. Delete generated output only if you accept losing that stale fallback.

Normal stdout contains only changed relative paths, one per line. Diagnostics go to stderr without titles, coordinates, source URLs, response bodies, or tokens. Later successful checks update freshness timestamps even if cue text is unchanged.

| Exit | Meaning |
|---|---|
| `0` | All requested source/week results complete |
| `2` | Safe output with stale/unavailable sources |
| `1` | Fatal configuration, format, identity, filesystem or cancellation error; do not publish |

Each HTTP request is capped at 20 seconds and 4 MiB; sources at 100 pages/10,000 records per week, optional Plex enrichment at 100 distinct items. The CLI has a 10-minute total deadline and handles SIGINT/SIGTERM. Selected targets are preflighted before any mutation. Writes use same-directory temporary files and atomic per-file rename, not a cross-file transaction. A fatal run may have written earlier files if a later write fails; never publish that checkout. Do not overlap writers; rerun locally or retry publication from a fresh checkout.

## Container

```sh
docker build -f deploy/Dockerfile -t funnel:local .
docker run --rm --network none funnel:local --help
# External private env file; writable scratch vault owned by UID/GID 10001.
docker run --rm --read-only --tmpfs /tmp \
  --env-file /private/path/dev.env \
  --mount type=bind,src=/path/to/scratch-vault,dst=/vault \
  funnel:local sync --vault /vault --week 2026-W39 --dry-run
```

The image runs as `10001:10001`, includes CA certificates/Madrid timezone data plus Git/SSH/shell, and has an exec-form CLI entrypoint. Ensure mounts are writable by that identity; new notes/directories are private (`0600`/`0700`), existing note permissions are preserved. Use a trusted private CA installation rather than disabling TLS. SSH authentication must use externally provided keys/agent and verified known hosts. No scheduler, Kubernetes assets or deployment is provided. Build context allows only required Go files, the explicit synthetic golden and helper/build files. Never put secrets or live data in source files.

Verified runtime: Linux ARM64, with synthetic services on an isolated temporary Docker bridge and an owned temporary vault volume. `deploy/container_test.sh` verifies non-root/read-only execution, denied writes, cancellation, stale recovery and a Madrid DST transition with `TZ=Pacific/Honolulu`. Its stub/shim publisher tests need executable tmpfs; production CLI temp storage does not.

## Optional Git publication

`deploy/publish.sh` is separate from Go; the image also includes it as `/usr/local/bin/funnel-publish`. Set `FUNNEL_GIT_REMOTE`, `FUNNEL_GIT_BRANCH`, `FUNNEL_GIT_AUTHOR_NAME`, `FUNNEL_GIT_AUTHOR_EMAIL`, and `TMPDIR` (a writable private temporary root). Remote transport must be verified HTTPS, SSH with verified host keys, or a local path for tests. Credentials stay in an external credential helper or SSH agent/key mount, never the URL. `FUNNEL_BIN` optionally selects the trusted executable (default `funnel`).

```sh
# Operator supplies the Git configuration and source env separately.
# No production remote is invoked by the tests below.
sh deploy/publish.sh
# In the image, externally bound the complete publishing attempt:
docker run --rm --read-only --tmpfs /tmp \\
  --env-file /private/path/publisher.env --entrypoint /bin/sh \\
  funnel:local -c 'exec timeout 900 sh /usr/local/bin/funnel-publish'
```

Each attempt uses and deletes its own private fresh checkout, never your mounted vault. Exact reported paths must match the entire Git change set and carry Funnel ownership/schema/week headers and cue markers. No whole-folder staging, deletion, force-push, rebase, automatic conflict resolution, or internal retry. Status `2` remains degraded after publication; fatal runs never publish. No changes means no commit.

On push failure, remote fetch/ancestry checks can confirm an accepted commit even if another writer advanced the branch. Failed verification reports **unknown**, not definite non-publication. Check remote state before retrying. If the commit is absent, rerun the whole helper from a fresh checkout; do not reuse its discarded worktree. Git raw output is captured privately and removed; the trusted CLI's already-redacted source/week stderr is forwarded. SIGTERM stops the active child and cleans up the checkout. HTTPS stalls are bounded by Git's 30-second low-speed timeout; provide an outer execution deadline (image `timeout` example above, or a native supervisor), bounded credential-helper/SSH connection behavior, and external overlap prevention.
